# ESC-0003 — Corrected memory fit conflicts with committed default-profile envelopes

## Context

TASK-0010 completed the product tier definition and correctly found that
TASK-0008's provisional model charges the host reserve twice. Its approved
replacement fits a preset against its committed footprint, without the extra
`-2.5` subtraction. Engineering compatibility review found two resulting
conflicts: `phi-4-14b` has an 11.75 GB footprint but its `good` profile has a
10g limit; `devstral-small-v25.07` has a 17.5 GB footprint but its `medium`
profile has an 8g limit. Calling either `runnable_presets/FIT` would contradict
the product's executable-today and honest-derived-recommendation contracts.

## Options

- **Adjust the committed profile memory limits.** Keeps every corrected-fit
  preset runnable with its default profile; cost: changes generated runtime
  resource envelopes and requires engineering/configuration validation.
- **Keep the profile limits and emit an explicit profile-envelope exclusion.**
  Preserves current generated configuration; cost: a machine may fit a model's
  footprint yet receive no runnable result until a compatible profile exists.
- **Separate catalog recommendation from executable partition.** Shows the
  corrected product recommendation but withholds `FIT` until its profile fits;
  cost: two visible classifications increase operator explanation and test
  surface.

## pm-orchestrator recommendation

**Option 2: keep current profile limits and emit an explicit exclusion/gap.**

It preserves the committed runtime envelope while preventing a false executable
claim. The exclusion must name the profile-envelope mismatch and next action;
it must retain disk gating, unknown-RAM behavior, `basis`, `confidence`,
`undetermined_inputs`, cgroup/VM observability, and the derived/no-runtime-
guarantee wording. A later measured profile-limit adjustment can promote the
affected preset without revising the tier taxonomy.

## Director decision — 2026-07-26

**Approved Option 2.** Keep the committed profile memory limits and emit an
explicit, non-FIT profile-envelope exclusion/gap when a model footprint fits
but its committed default profile does not. This authorizes the TASK-0008 plan
amendment and its bounded implementation; it does not authorize changing any
profile `mem_limit` values.
