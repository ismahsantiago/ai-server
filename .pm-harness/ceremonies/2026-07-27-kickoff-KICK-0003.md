- **Date**: 2026-07-27
- **Created by**: pm-orchestrator
- **Status**: pending Director approval

## Initiative
Cross-instance server deployment and shared AI operational learning

## Proposed plan

1. Audit `.pm-harness/`, `.claude/`, `.codex/`, `.opencode/`, and root
   activation files for portability, secrets, caches, host-specific state, and
   reproducibility value.
2. Define an explicit tracked allowlist and ignored denylist; never commit
   dependencies, credentials, sessions, machine-local permissions, or caches.
3. Preserve the governed project context needed by a second equivalent AI
   instance: harness contracts, plans/state/memory/evidence, wiki, standards,
   roster skills, and native activation pointers.
4. Add an English next-event handoff that instructs the next instance to clone
   on the server, verify the checkout, resume from project evidence, and capture
   observations without claiming unexecuted runtime results.
5. Validate a clean clone/materialization path, run secret and harness checks,
   execute applicable repository gates, then commit and publish the bounded
   portability packet.

## Per-area specifications (draft, one subsection per applicable area)

### Product

- The next event is a clone of this repository onto the intended server.
- A separate instance of the same AI provider/model family will continue work.
- The exercise studies continuity between equivalent, independent AI instances.
- The handoff must state the experiment objective, current limitations, and
  first governed commands.
- Experience must be captured as evidence and memory, not as unsupported claims.
- The repository remains generator-first and localhost-only.
- Real GGUF runtime validation begins only after an authorized model is present.

### Engineering

- Track `.pm-harness/` as project-local shared context for the same repository.
- Track only native adapter sources/pointers required for Claude and OpenCode.
- Keep `.codex/` absent unless a real project-local Codex surface is generated.
- Exclude `.opencode/node_modules/`, caches, build outputs, and installed packages.
- Exclude `.claude/settings.local.json` because permissions are host-local.
- Verify the packet from a clean checkout without relying on ignored local state.
- Preserve append-only task, decision, evidence, and memory history.

### Security

- Scan all candidate files for secrets, credentials, tokens, private keys, and
  sensitive host paths before staging.
- Never track provider authentication, sessions, environment files, or local
  permission grants.
- Use an allowlist-oriented `.gitignore` contract for AI integration surfaces.
- Treat model weights and runtime logs as local/external evidence by default.
- Confirm that project-local sharing does not create cross-project/global state.
- Keep LAN fail-closed and avoid publishing host/network details.
- Require `git diff --cached` and clean-checkout verification before commit.

### Operator experience

- Provide one concise handoff document readable by the next AI instance first.
- Include clone, environment, harness validation, status, and recovery commands.
- Explain which directories are authoritative and which are generated pointers.
- State that the new instance must inspect live state before trusting summaries.
- Give a capture protocol for observations, failures, decisions, and benchmarks.
- Keep instructions provider-neutral where possible while naming tested surfaces.
- Make missing prerequisites explicit rather than silently regenerating them.
