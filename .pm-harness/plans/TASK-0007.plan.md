## Risks
- Prior audit content could bias the new run. Mitigation and rollback: prohibit opening prior audit reports, allow only `audits/INDEX.md` and `audits/standards/` state, and discard/restart any dimension pass that violates this boundary.
- Remediation could contaminate the pre-remediation audit evidence. Mitigation and rollback: complete and hash the required audit deliverables before changing product source; revert only TASK-0007-owned remediation changes if the snapshot was not frozen, never user-owned changes.
- Parallel roles could overlap or overwrite changes. Mitigation and rollback: assign findings by declared ownership in the remediation ledger, use small file scopes, inspect the dirty worktree before each edit, and revert only the conflicting TASK-0007 hunk after coordination.
- Security, dependency, container, or network fixes can be high risk or environment-dependent. Mitigation and rollback: require security-engineer review, keep localhost and least-privilege defaults, avoid publishing or live infrastructure mutation, and escalate irreversible or scope-changing actions before execution.
- Docker or live model serving may be unavailable on the current host. Mitigation: distinguish static/configuration validation from live-runtime evidence, record literal command failures, and do not claim runtime verification that did not occur.
- Updating both `audits/standards/` and `.pm-harness/standards/` can create duplicate or contradictory rules. Mitigation: keep the audit-standard finding lineage and the PM Harness APR enforcement lineage explicit, cross-reference them, and never silently resolve contradictions.
- Dependency remediation may require network access or introduce incompatibilities. Mitigation and rollback: prefer the smallest compatible pinned change, run `pip check` and tests, preserve the prior declaration in git history, and escalate major/runtime-breaking upgrades.
- Generated workspaces can overwrite operator edits. Mitigation and rollback: treat templates/manifests as canonical, regenerate only controlled outputs with explicit force semantics, and do not delete or replace unrelated generated directories.
