  benchmarking is blocked unless a test model is sourced this run.
  Mitigation and rollback: the baseline todo's branch (b) is a first-class,

  is scored on documented backend-support characteristics only, never on
  invented numbers.

  (`HTTP status: not-tested`, `Model path: /models/placeholder.gguf`,
  `Profile: unknown`); there is no real llama.cpp baseline in this repo
  today. Mitigation and rollback: state this gap explicitly in `Evidence
  status` regardless of which baseline-todo branch is reached; never let the
  document imply a baseline exists when it does not.

  failure under this role's SKILL.md error path. Mitigation and rollback: any
  number in the document that was not produced by a command actually run
  this session must be attributed to its source (vendor docs, another
  party's benchmark) or marked "documented characteristic, not measured
  this run" — never presented bare.
- Network access for fetching upstream documentation (docs.docker.com,
  Ollama docs) may be unavailable during execution. Mitigation and rollback:
  where a citation cannot be fetched, the affected row/section states
  "source unreachable at evaluation time; relying on the two pre-established
  kickoff findings only" instead of asserting from unverified memory.
- `security-engineer` holds a blocking veto over the DMR question; a
  contested or delayed verdict could stall Phase M/N/X indefinitely.
  Mitigation and rollback: TASK-0009 does not transition to `in_review`
  until engineering-manager records a sign-off or an explicit objection on
  the task; if objected, the recommendation section is revised (not the
  scoring rows), and the revision is tracked as a plan amendment, not a
  silent rewrite.
- Scope creep into Phase M/N/X implementation. Mitigation and rollback: this
  plan's todos only produce a decision document and a review handoff; any
