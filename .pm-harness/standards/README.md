# Standards system

Quality rules born from real findings (audits, reviews, incidents). Goal: no
finding of the same type ever happens twice. This directory is seeded by the
installer with the protocol only; the per-dimension rule documents are
generated by the team as findings appear (HARNESS-SPEC §10).

## Efficient loading protocol (Gate 0)

Agents do NOT load this whole directory. At task start:

1. Always read `GATES.md` (one page: gates + Definition of Done).
2. Classify the task and load ONLY the applicable rule documents:

| Task touches | Load |
|---|---|
| API, data, secrets, auth | `SECURITY.md` |
| Any source code | `CODE.md` |
| UI components, pages, copy | `DESIGN.md` |
| Core product flows | `PRODUCT.md` |
| Schema, dependencies, CI, scripts | `OPS.md` |
| Personal data or third-party data flows | `LEGAL.md` |
| `.pm-harness/`, platform adapter dirs | `HARNESS.md` |

(A document that does not exist yet simply has no rules — create it with the
first rule that needs it.)

3. Before integrating: `GATES.md` Gate 1.
4. A defect no rule covers → improvement protocol in `IMPROVEMENT.md` (APR
   entry in the same change).

## Rule format

Each rule has: a **stable ID** (`STD-XXX-nn`, XXX = dimension) · an
**imperative statement** · a **mechanical verification** (a concrete command
whenever possible; "manual review" otherwise) · an **origin** (the finding
that produced it).

Budget: max ~20 rules per document. A full document means retiring a rule
before adding one (see `IMPROVEMENT.md`).
